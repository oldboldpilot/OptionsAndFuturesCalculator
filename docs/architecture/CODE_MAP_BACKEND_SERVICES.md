## backend/src/main.cpp
`backend/src/main.cpp` is the entrypoint and bootstrap coordinator for the backend binary. It manages the boot sequence, environment configuration, transport limits, service registration, hook injection, background scheduling, and the server event loop.

### Boot Sequence
The boot sequence proceeds sequentially in `RunServer()` (`backend/src/main.cpp:80-169`) as follows:
1. **Entrypoint & Subcommand Check** (`backend/src/main.cpp:175-185`): `main()` inspects command-line arguments. If `argc > 1` and `argv[1] == "issue-key"`, execution delegates directly to `IssueKeyMain(argc, argv)` (`backend/src/main.cpp:182`) to mint cryptographic API keys using the identical hashing routines as the server verification path. Otherwise, `RunServer()` executes.
2. **Listen Address Resolution** (`backend/src/main.cpp:81`): Calls `resolve_port()` (`backend/src/main.cpp:65-78`) to determine the TCP port and formats `server_address` as `0.0.0.0:<port>`.
3. **FIPS Cryptographic Policy Enforcement** (`backend/src/main.cpp:87-101`): Calls `fips::apply_from_environment()` (`backend/src/main.cpp:88`) **before** the transport listener binds. Under `FIPS_MODE=required`, if the OpenSSL FIPS provider and default FIPS properties fail to load, the process logs a fatal error to `std::cerr` and halts immediately via `std::exit(1)` (`backend/src/main.cpp:99`).
4. **ServerBuilder Setup** (`backend/src/main.cpp:103-104`): Configures `grpc::ServerBuilder builder`:
   - Binds `server_address` with `grpc::InsecureServerCredentials()` (`backend/src/main.cpp:103`).
   - Restricts the maximum receive message size to `kMaxRequestBytes = 1048576` (1 MiB) (`backend/src/main.cpp:33, 104`).
5. **Service Registrations**:
   - `options_calculator::service::RegisterCalculatorService(builder)` (`backend/src/main.cpp:106`): Registers the core options and futures pricing service (`calculator.OptionsCalculator`).
   - `options_calculator::finance::RegisterFinanceService(builder, {.refresh = &state_refresh::run_refresh, .read = &state_refresh::read_assumptions})` (`backend/src/main.cpp:112-114`): Registers the financial mathematics service (`sensen.finance.Finance`), injecting hooks for state assumption refreshes and reads.
   - `options_calculator::assistant::RegisterAssistantService(builder)` (`backend/src/main.cpp:124`): Registers the options strategy assistant service (`calculator.assistant.StrategyAssistant`).
   - `options_calculator::mortgage_assistant::RegisterMortgageAssistantService(builder)` (`backend/src/main.cpp:140`): Registers the mortgage/TVM assistant service (`mortgage.assistant.MortgageAssistant`).
6. **Server Start** (`backend/src/main.cpp:142`): `std::unique_ptr<grpc::Server> server(builder.BuildAndStart());` binds the socket and starts request worker threads.
7. **Security Posture Logging** (`backend/src/main.cpp:147-158`): Queries `options_calculator::auth::KeyRegistry::instance()` to log whether API key authentication is disabled or active (`ENFORCE`, `WARN`, or `OBSERVE`), the registered key count, and transport limits.
8. **Background Scheduler Startup** (`backend/src/main.cpp:163-164`): Instantiates and starts `static state_refresh::Scheduler state_scheduler;`. Started strictly after the listener binds so slow initial ticks cannot delay orchestrator health checks.
9. **Event Loop & Shutdown Path** (`backend/src/main.cpp:168`): Executes `server->Wait()`, blocking the main thread until server shutdown. On process exit, RAII destructors reclaim resources: `server` releases transport bindings, and `state_scheduler` terminates its background worker thread. Unhandled standard exceptions in `main()` are caught at `backend/src/main.cpp:186-189`, logging to `std::cerr` and returning exit code 1.

### Hook Injection & Architecture Rationale
`backend/src/main.cpp` is the sole compilation unit that binds the concrete database-backed implementations of `state_refresh` and `strategy_store`:
1. **`StateRefreshHooks`**: Defined in `backend/src/modules/finance_service.cppm:32-39` as two `std::function` members (`refresh` and `read`). `main.cpp:113-114` injects `&state_refresh::run_refresh` and `&state_refresh::read_assumptions`. Injected rather than linked because `finance_service` does not link `libpq`; taking the address of database functions directly inside `finance_service.cpp` would introduce a dependency on PostgreSQL, breaking lightweight pricing test binaries (`test_option_pricing_service`, `test_finance_service_validation`) that link `finance_service` without `libpq`.
2. **`IStrategyStore`**: Declared as an abstract interface in `backend/src/modules/strategy_store.cppm:127-145` and accepted by `CalculatorServiceImpl` (`backend/src/modules/calculator_service.cpp:1070`). `main.cpp` calls `RegisterCalculatorService(builder)` (`backend/src/main.cpp:106`), which calls `store::make_pg_strategy_store(database_url)` (`backend/src/modules/calculator_service.cpp:1898`). In tests, `RegisterCalculatorServiceForTest` accepts a custom `std::shared_ptr<store::IStrategyStore>` (`backend/src/modules/calculator_service.cppm:47-50`), permitting in-memory fakes (`FakeStore`) to be injected without PostgreSQL reachability.

### Key Invariants, Refusals & Failure Modes
- **Leg Limit Hard Bound**: Enforced at `backend/src/modules/calculator_service.cpp:1188-1193`: requests with $>20$ legs (`kMaxLegs = 20`, `:485`) are rejected with `INVALID_ARGUMENT` before authentication or quota execution.
- **Grid Dimension Bounds & Degradation**: `resolve_grid_steps` (`backend/src/modules/calculator_service.cpp:508-523`) clamps `price_steps` to `kMaxPriceSteps = 500` (`:445`) and `date_steps` to `kMaxDateSteps = 180` (`:446`). If `price_steps * date_steps > kMaxGridCells = 20000` (`:447`), `date_steps` is reduced (`:519-521`) to preserve full resolution on the primary price curve.
- **Four Price-Grid Sweeps**:
  1. `max_profit` sweep (`backend/src/modules/calculator_service.cpp:749-754`): evaluated across `price_grid` points at curve expiration (`ctx->curve`).
  2. `max_loss` sweep (`backend/src/modules/calculator_service.cpp:749-755`): evaluated across `price_grid` points at curve expiration.
  3. `break_even_prices` sweep (`backend/src/modules/calculator_service.cpp:769-780`): detects zero-crossings across adjacent `expiry_pnl` points and interpolates roots.
  4. Lognormal probability distribution sweep (`backend/src/modules/calculator_service.cpp:324-350, 965-992`): `lognormal_over` evaluates GBM densities across `price_grid` to derive PoP, EV, and VaR/CVaR.
- **Separate Matrix Price Grid**: `matrix_price_grid` (`backend/src/modules/calculator_service.cpp:545, 684-733`) is isolated from `price_grid`. Custom user zooms via `matrix_price_min` and `matrix_price_max` adjust `matrix_price_grid` only (`backend/proto/calculator.proto:112-118`). If the matrix shared `price_grid`, zooming would truncate the domain of the four sweeps, corrupting max profit, max loss, breakevens, and PoP.
- **Saved Scenario Subject Invariant**: Enforced in `check_saved_scenarios_entitlement` (`backend/src/modules/api_key.cpp:487-493`). An empty `identity.subject` returns `UNAUTHENTICATED`. This check precedes gate-mode evaluation, preventing unowned database writes.
- **Asian Option Refusal**: Enforced at `backend/src/modules/calculator_service.cpp:638-665`. Position legs with `asian_type != NOT_ASIAN` are refused with `FAILED_PRECONDITION` (`:658-664`) because payoff diagrams are indexed against terminal spot price $S_T$, whereas Asian options settle on average path price $\bar{S}$. Malformed averaging states ($<2$ or $>200$) are refused earlier with `INVALID_ARGUMENT` (`:650-656`).

### Gotchas
- **Silent Halt on Partial SGEE Graph**: If an action name is unregistered or fails without setting `ctx->status`, SGEE's interpreter halts silently. Two postconditions guard against this: the terminal-state check verifies the entity reached `Done` (`backend/src/modules/calculator_service.cpp:1283-1296`), and the did-compute check verifies `pnl_matrix_size() == price_steps` (`backend/src/modules/calculator_service.cpp:1306-1315`).
- **Locale-Dependent Date Formatting Trap**: The 2D matrix ISO-8601 dates are formatted with `std::format("{:04}-{:02}-{:02}", ...)` (`backend/src/modules/calculator_service.cpp:821-823`). Streams (`std::ostringstream`) inherit the global locale, which logger initialization sets to `en_US.UTF-8`, grouping years with commas ("2,026") and breaking client date parsing.

### Engine Error Mapping Helper
Engine computation failures returning `std::expected<T, std::string>` are mapped to gRPC status codes via the template helper `fail` (`backend/src/modules/finance_service.cpp:216-219`):
```cpp
template <typename T>
[[nodiscard]] auto fail(const std::expected<T, std::string>& e) -> Status {
    return Status(grpc::StatusCode::FAILED_PRECONDITION, e.error());
}
```
`fail()` maps all engine computation error strings directly into `grpc::StatusCode::FAILED_PRECONDITION`.

### Key Invariants, Refusals & Failure Modes
- **Dates-in-Days to Seconds Bridge**: Enforced by `dates_to_seconds` (`backend/src/modules/finance_service.cpp:4446-4477`), invoked by `ComputeXNPV` (`:1963`) and `ComputeXIRR` (`:1986`). On the wire (`finance.proto`), dates arrive as day offsets from an epoch (e.g. 372.0 days). `sensen::xnpv` and `xirr` divide elapsed times by $31,536,000$ seconds per year ($86,400 \times 365$). Passing raw days caused discount factors to collapse to 1.0 ($e^0$), returning undiscounted sums. `dates_to_seconds` multiplies each day offset by `kSecondsPerDay = 86'400.0` (`:4417, 4471`). If dates span $<1.0$ day across $>1$ cash flows, it refuses with `INVALID_ARGUMENT` (`:4452-4458`). If span exceeds `kMaxCashFlowDaySpan = 36'525.0` days (100 years), it refuses with `INVALID_ARGUMENT` (`:4459-4467`).
- **TVM Solvability Pre-Check**: Implemented in `check_tvm_solvable` (`backend/src/modules/finance_service.cpp:4326-4339`), called in `ComputeRate` (`:1354`) and `ComputePeriods` (`:1381`). Solves the annuity balance $PV(1+r)^n + PMT \cdot \text{annuity}(r, n) + FV = 0$. When $FV = 0$, a real solution exists if and only if $PV$ and $PMT$ have opposite signs. If $PV$ and $PMT$ share the same sign (and neither is zero), money flows in only one direction. Refuses with `grpc::StatusCode::INVALID_ARGUMENT` (`:4331-4338`).
- **ComputePeriods Non-Positive Post-Check**: Enforced at `backend/src/modules/finance_service.cpp:1391-1397`. `sensen::nper_fn` computes periods via a closed-form formula without an iterative solver. Inputs that imply non-positive periods return $\le 0.0$. The post-check catches `*r <= 0.0` and returns `grpc::StatusCode::INVALID_ARGUMENT` (`:1392-1396`).
- **MACRS Supported-Class Refusal**: Enforced in `ComputeDepreciation` (`backend/src/modules/finance_service.cpp:2131-2158`). Checks `if (!sensen::macrs_supports(request->recovery_period()))` (`:2147`). Supported GDS recovery periods are strictly 3, 5, 7, 10, 15, and 20 years. Unlisted recovery periods—specifically 27.5-year residential rental and 39-year nonresidential real property—are refused with `grpc::StatusCode::INVALID_ARGUMENT` (`:2149-2156`). They are refused rather than approximated because real-property MACRS mandates the mid-month convention, which requires the month placed in service—a field `DepreciationRequest` does not carry.
- **Rent-vs-Buy Shape Dispatch**: `RentVsBuyRequest` carries two mutually exclusive representations: legacy composite (`monthly_piti_and_maintenance`) and granular amortising (seven fields: `home_price`, `down_payment`, `mortgage_interest_rate`, `loan_term_years`, `property_tax_rate`, `annual_home_insurance`, `annual_maintenance_rate`). `classify_decimal_field` (`backend/src/modules/finance_service.cpp:454-486`) maps strings to `FieldSignal` (`Absent`, `Zero`, `Negative`, `Positive`, `Malformed`). `join_group_signal` (`:506-528`) collapses the seven granular fields into one signal. `decide_rent_vs_buy_shape` (`:535-566`) provides a total decision matrix over $5 \times 5$ signals:
  - If either signal is `Malformed` $\to$ `RentVsBuyShape::RefuseMalformed` (`:539-541`).
  - If composite is `Negative` $\to$ `RentVsBuyShape::RefuseNegativeCost` (`:545-547`).
  - If both composite and granular are `Positive` $\to$ `RentVsBuyShape::RefuseBothShapes` (`:553-555`, returns `INVALID_ARGUMENT`).
  - If only composite is `Positive` $\to$ `RentVsBuyShape::Legacy` (`:556-558`).
  - If only granular is `Positive` $\to$ `RentVsBuyShape::Amortising` (`:559-561`).
  - If both are `Absent` or `Zero` $\to$ `RentVsBuyShape::RefuseNeitherShape` (`:565`, returns `INVALID_ARGUMENT`; does not fabricate a default loan).
- **Batch RPC Per-Scenario Error Handling & Parallel Threshold**:
  - In `ComputeRentVsBuyBatch` (`backend/src/modules/finance_service.cpp:2947-3058`), $n \le 1000$ (`kMaxScenarios`, `:2961`); larger batches return `INVALID_ARGUMENT` (`:2963-2968`). Quota charges upfront for $n$ scenarios (`:2978`). Response slots are pre-allocated serially (`:2991-2994`) to eliminate data races on protobuf structures. In `run_one` (`:3014-3023`), scenarios execute independently: successful results populate `slot->mutable_result()`, while failures populate `slot->set_error(st.error_message())`, preventing one failed scenario from aborting the batch. Execution threshold: `kParallelThreshold = 64` (`:3042`). Batches with $n < 64$ run sequentially (`:3043-3048`); batches with $n \ge 64$ execute via `sensen::parallel::parallel_for` (`:3050-3056`).
  - In `ComputeAmortizationBatch` (`backend/src/modules/finance_service.cpp:1539-1648`), ragged repeated arrays (mismatched sizes across `loan_amounts`, `annual_rates`, `term_months`, `extra_payments`, `pmi_rates`, `home_values`) return `INVALID_ARGUMENT` (`:1556-1570`). `term_months` is bounded to $\le 1200$ (`:1572`). Raw wire doubles are validated with `require_finite` and `check_double_magnitude` (`:1597-1628`) to prevent undefined behavior in `BigDecimal(double)` conversions.

### Gotchas
- **Adversarial Compound Growth Overflows**: `check_compound_growth_safe` (`backend/src/modules/finance_service.cpp:568-583`) and `check_compound_growth_safe_periods` (`:586-615`) reject rate and term combinations where $(1 + r)^n$ would exceed 40 natural log units ($\approx 2.35 \times 10^{17}$-fold growth). Without this joint check, reasonable individual values (e.g. 6% annual rate compounded annually over 1200 monthly periods) silently wrap `BigDecimal`'s `__int128` fixed-point storage.
- **Strict Decimal Grammar vs BigDecimal::parse**: `parse_decimal` (`backend/src/modules/finance_service.cpp:69-102`) validates strings against `[-+]?[0-9]*\.?[0-9]+` before handing them to `sensen::BigDecimal`. `BigDecimal::parse` skips non-digit characters without reporting errors ("abc" becomes 0; "12x3" becomes 123), which would allow typos to become numbers on a public API.

- **Independent Assistant Pipelines**: `mortgage_assistant_service` and `assistant_service` instantiate entirely separate LLM pipelines, worker threads, and model weights (`MORTGAGE_MODEL_PATH` vs `MODEL_PATH`). - **TVM Sign Inversion Applied After Grounding**: `apply_tvm_sign_convention` runs strictly **after** GP-ARA verification (`backend/src/modules/mortgage_assistant_service.cpp:2805, 2822`). Grounding requires emitted numbers to match the user's literal text ("$7,751.77"). Applying sign negation before verification would cause the grounding gate to reject the negative value as ungrounded.
