# OptionsAndFuturesCalculator Update & Commit Policy
# Last Updated: August 2, 2026

Remote repositories are both GitHub and Gitea (self-hosted; credentials in
config/.env). Create the Gitea repo if it does not exist before pushing. Both
remotes are already configured and SSH login is set up.

This repository contains a vendored submodule, backend/sensen, which has its
OWN update policy at backend/sensen/config/update_policy.txt and its own pair of
remotes. A change touching sensen must satisfy BOTH policies, and sensen is
pushed separately — a submodule pointer bump in this repo does not push sensen.

## Scope

This policy covers everything in the repository:

- backend/  — C++23 engine serving three gRPC services (calculator.OptionsCalculator,
              sensen.finance.Finance, calculator.assistant.StrategyAssistant)
              behind Envoy, deployed to Railway as a container
- frontend/ — Next.js static export served by a Cloudflare WORKERS static-assets
              deployment (frontend/wrangler.toml). NOT Cloudflare Pages; the Pages
              project still exists but nothing points at it.
- workers/  — Cloudflare Workers (billing: Stripe checkout, licence minting,
              Supabase tier writes)
- backend/sensen — vendored inference/finance library (see its own policy)

## Pre-Commit Checklist

1. **Build Verification**
   - Backend: `cmake -G Ninja -B backend/build -S backend && ninja -C backend/build`
     Zero warnings, zero errors. The canonical toolchain is clang 23 with
     libc++ (moved from 22 on 2026-08-29); do not mix stdlibs (see CLAUDE.md).
     Configure with -DCMAKE_CXX_COMPILER=/usr/local/bin/clang++ and
     -DCMAKE_CXX_COMPILER_LAUNCHER=ccache -- NOT the ccache shim as the
     compiler, which breaks sensen's std.cppm path walk.
   - Container build is the real gate for deployment, because three classes of
     bug are invisible locally — private-model fetch credentials, BuildKit
     secret mounts, and TBB availability:
     `docker build -t options-backend backend/`
   - Frontend: `cd frontend && npm run build` (also runs the type check)
   - Workers: `cd workers/billing && npx tsc --noEmit && npx wrangler deploy --dry-run`

2. **Test Suite**
   - `ctest --test-dir backend/build` — all tests must pass
   - `backend/build/smoke_client` — verifies the finance surface against
     independent identities (put-call parity, price/yield inversion, schedule
     closure, closed-form annuity), NOT against figures the engine produced
     earlier. Set SMOKE_PRO_LICENCE / SMOKE_PRO_BEARER so the Pro gate is
     exercised in BOTH directions; a gate proven only to refuse is
     indistinguishable from one that refuses the paying customer.
   - Note: native gRPC does not survive the Railway ingress. Do not treat a
     smoke_client failure against api.optionsandfuturescalculator.com as a
     service outage — verify production through the browser path or railway logs.
   - Frontend: verify the static export contains no secret material before
     deploying (grep the build output for sk_live_/rk_live_/whsec_/service-role
     patterns). The frontend is public by construction.

3. **Documentation Updates** (required for every push)
   - Update CLAUDE.md — architecture, gRPC surface, deployment, DNS, and any
     operational constraint that is not otherwise represented in the repository
   - Update docs/INDEX.md if documents were added or removed, and verify every
     link in it still resolves
   - Update docs/PRD_OPTIONS_AND_FUTURES_CALCULATOR.md (status, scope changes)
   - Update the relevant API document when a service contract changes:
     docs/FINANCE_API.md, docs/BUSINESS_API.md, docs/API_SECURITY.md
   - Update backend/docs/ for engine-internal facilities (e.g. TENSOR_OBSERVER.md)
   - Update workers/billing/README.md when the billing flow or its required
     Stripe webhook events change
   - Keep documentation organised by topic under docs/:
       docs/api/, docs/guides/, docs/architecture/, docs/release_notes/,
       docs/technical/, docs/session_logs/, docs/other/
   - Record what was measured, not what was expected. Where a prediction turned
     out wrong, keep the wrong prediction next to what replaced it — that is
     usually the most useful part of the record.

4. **Session State**
   - Save a session log to docs/session_logs/ named
     session_YYYY-MM-DD_<topic>.md

## Secrets

- config/.env is gitignored and MUST stay that way. It is synced to the NAS, not
  to any git remote.
- Zero hardcoded secrets anywhere in tracked files; credentials come from the
  environment only.
- Never print a credential value. Redact remote URLs containing credentials
  before showing them: sed -E 's#//[^@]*@#//<redacted>@#'
- config/.env is read by tooling as line-oriented KEY=VALUE. Do not paste
  multi-line shell examples into it — a pasted curl snippet once put a live
  Cloudflare token on a continuation line, where a naive parser surfaced it.
- The AdSense publisher id and ad slot ids are NOT secrets.
- Stripe publishable (pk_live_) and Supabase anon keys are designed to be public.

## Commit Message Format

- Conventional commits (feat:, fix:, docs:, refactor:, chore:)
- Say what changed and why. Where a bug is fixed, state the mechanism and how it
  was found, not merely that it is fixed — the mechanism is what stops it
  recurring.
- State plainly what was left out and why, when scope was deliberately not
  finished.
- NO AI co-author attributions.

Example:

```
fix(backend): Stop casting a raw logit to a token id on CPU builds

GenerationConfig defaults compute_backend to AUTO, which the pipeline counted
as a GPU request unconditionally. That enabled on_device_sampling, a contract
only the CUDA decode block honours, so the CPU path cast logits[0] to a token
id and emitted punctuation.

Fixed at source and independently in the service, so the fix does not depend on
which sensen commit is pinned.
```

## Post-Commit Actions

1. **Push to BOTH remotes**
   - `git push origin master && git push gitea master`
   - If backend/sensen changed, push sensen to its own two remotes as well, and
     satisfy backend/sensen/config/update_policy.txt

2. **Backup to NAS**
   - Run: `bash scripts/backup_to_nas.sh`
   - Target: /home/muyiwa/PrimaryNAS/DataFolder/PycharmProjects/OptionsAndFuturesCalculator
   - The script passes --no-links deliberately: the NAS is CIFS and cannot
     create symlinks, so rsync reports "Operation not supported (95)" and exits
     23 without it. An exit 23 from an ad-hoc rsync is usually this, not data
     loss — verify file contents before assuming a failed transfer.
   - config/.env IS included in the NAS backup by design.

3. **Deploy** (when the change is user-facing)
   - Frontend: `cd frontend && npm run build && npx wrangler deploy`
     This is a WORKERS static-assets deployment (frontend/wrangler.toml), not
     Cloudflare Pages. `wrangler pages deploy` still succeeds and prints a URL,
     but the live domains are Workers custom domains, so it deploys nothing a
     user can see — that mistake cost five "completed" frontend deploys while
     the apex served a stale bundle pointing Supabase at localhost.
     "Deployment complete" is not the gate — re-verify every referenced asset
     actually resolves, and grep the served bundle for the config you expect.
     See docs/guides/ASSISTANT_EVALUATION.md for the general form of this trap.
   - Backend: `railway up --detach` (project fearless-amazement,
     service options-calculator-backend)
